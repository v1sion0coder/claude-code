# Координация двух AI (Claude + Codex/GPT) — файловый протокол

**Статус: ПРЕДЛОЖЕНИЕ для согласования** (владелец + Codex могут менять). Ничего внешнего
это не запускает: только файлы в git. Коннекторы, письма, публикации, расходы — вне этого
протокола и только с разрешения владельца.

## Главный факт об архитектуре (важно)
- **Claude** работает в облачном контейнере (Linux, `/home/user/claude-code`). Локальный
  диск владельца `D:\Azalea\AI\AI_OFFICE` **Claude недоступен**.
- **Codex** работает на локальной машине владельца.
- **Единственный общий канал между ними — этот git-репозиторий**
  (`github.com/v1sion0coder/claude-code`, ветка `claude/affiliate-program-agents-fox443`).
  Никакой общей «живой» файловой системы нет. Передача результатов = **commit + push → pull**.
- Чтобы Codex участвовал файлово: он должен иметь **git-доступ к этому репо** и работать в
  его клоне (а не только в `D:\...\AI_OFFICE`, если это другой проект). Если AI_OFFICE —
  отдельный проект, нужно решить: сливать его сюда или держать раздельно.

## Источники истины (не дублировать, не переписывать вручную)
- `affiliate/knowledge-base/programs.csv` — реестр программ (правится только через csv-парсер).
- `affiliate/knowledge-base/revenue.csv` — ФАКТИЧЕСКИЙ доход (единственная правда о прибыли).
- `affiliate/knowledge-base/criteria.md` — критерии отбора.
- `affiliate/reports/*`, `affiliate/content/*` — планы и контент (выходные материалы).

## Формат задачи
Одна задача = один файл в `affiliate/coordination/tasks/TASK-NNN-<slug>.md` со шапкой:

```
id: TASK-001
title: <кратко>
owner_ai: unassigned | claude | codex        # кто исполняет
reviewer_ai: claude | codex                  # кто делает независимое ревью
status: open | claimed | in_progress | in_review | done | blocked
inputs: <пути к входным файлам>
allowed_changes: <какие файлы можно менять/создавать; остальное трогать нельзя>
done_criteria: <проверяемый критерий готовности>
output: <путь к результату>
```

## Правила безопасной работы (вместо «блокировки записи»)
1. **Захват задачи (lock):** исполнитель меняет в файле задачи `owner_ai` и `status: claimed`
   → commit+push. Если двое захватили одновременно — это всплывёт merge-конфликтом (естественный лок).
2. **Не редактируй чужой источник:** ревьюер НЕ правит исходник, а пишет отдельный файл в
   `affiliate/reviews/<slug>.review.md`.
3. **Независимое ревью:** результат исполнителя проверяет `reviewer_ai` и ставит вердикт
   pass/fail по 4 правилам честности (см. `CLAUDE.md`).
4. **Только через git:** никаких «промежуточных результатов мимо репозитория».
5. **Границы:** коннекторы/почта/публикации/регистрации/расходы — НЕ в этом протоколе;
   только с явного разрешения владельца.

## Журнал решений
Значимые решения фиксируются в `affiliate/coordination/DECISIONS.md` (одна строка = одно
решение с датой и автором). Создаётся при первом решении.
